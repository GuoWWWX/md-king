# md-king 桌面端 UI/UX 设计稿说明 v1.0

> 用途：给设计师制作 Figma 原型与视觉稿。  
> 项目定位：面向 AI 生成 Markdown 内容的本地桌面工具，把 Markdown 稳定转换为可编辑、样式可控的 Word/WPS `DOCX` 文档。  
> 当前建议：先完成界面设计与交互原型，再基于设计稿重写前端。

---

## 当前实现提示（2026-06）

当前桌面端默认内置 Pandoc，普通用户无需单独安装。浏览器预览只展示前端和 simulated 转换状态，不代表真实桌面能力；真实 DOCX 输出、打开文件、配置持久化等请以 `pnpm tauri dev` 为准。模板样式编辑器已强化表格预览、列宽、边框、表头/表体与预设，但现阶段仍是前端草稿和预览，不应在 UI 中暗示已经能完整写回 `reference.docx`。右键菜单、悬浮球、托盘、CLI/MCP 等仍属于规划能力，设计稿里建议以“规划中/即将支持”弱化展示。

## 1. 产品名称

**md-king**

---

## 2. 产品一句话定位

面向 AI 时代的 Markdown 转 Word/WPS 工具，把 ChatGPT、Claude、DeepSeek 等 AI 生成的 Markdown 内容，一键转换为样式稳定、可编辑、可复用模板的 `DOCX` 文档。

---

## 3. 设计目标

### 3.1 核心目标

这个产品不是 Markdown 编辑器，也不是复杂办公软件，而是一个 **高频、轻量、专业的文档转换效率工具**。

设计需要突出：

1. **一键转换感**
   - 用户打开软件后，第一眼就知道可以拖文件、粘贴内容、选择模板、生成 Word。

2. **模板感**
   - 让用户明显感受到：不同模板会生成不同 Word/WPS 风格文档。

3. **专业可信感**
   - 适合报告、论文、公文、商务方案、技术文档等场景。
   - 不要做得太“玩具化”。

4. **本地安全感**
   - 强调“本地转换、不上传文档”。

5. **AI 文档场景感**
   - 用户常见行为是：从 AI 复制 Markdown，然后快速转成 Word/WPS。

## 4. 推荐整体视觉风格

### 4.1 风格关键词

- 现代
- 专业
- 轻量
- 干净
- 类办公工具
- 类 AI 效率工具
- 有一点高级感，但不要太花

### 4.2 参考风格方向

可以参考这些产品的视觉感觉：

- Notion：干净、块状布局、信息清晰
- Raycast：效率工具感、命令感
- Linear：现代、清晰、有质感
- Craft / Typora：文档工具感
- WPS / Microsoft Word 的专业办公氛围，但不要照搬传统 Office

### 4.3 不建议的风格

避免：

- 太花哨的渐变；
- 游戏化视觉；
- 大面积高饱和颜色；
- 太传统 Windows 工具软件风格；
- 复杂后台管理系统风格；
- 过多表格、过多边框。

### 7.2.5 模板修改 / 编辑模板流程

模板中心需要支持用户“直接修改模板”。这里的“修改模板”建议分成三层，避免一开始就做过重的 Word 样式编辑器。

#### 修改能力分层

| 层级 | 能力 | MVP 建议 | 说明 |
|---|---|---|---|
| 基础信息修改 | 模板名称、分类、说明、标签、是否默认 | 必须做 | 实现简单，用户感知强 |
| 外部编辑 DOCX | 用 Word/WPS 打开模板文件，用户直接改样式 | 必须做 | 最符合用户习惯，也是 Pandoc reference.docx 的正确编辑方式 |
| 应用内快速样式修改 | 标题字体、字号、颜色、正文样式、页边距等 | V1/V2 | 需要解析和写回 DOCX 样式，复杂度较高 |

因此设计上建议：

- MVP 先做“模板信息编辑 + 打开 Word/WPS 修改模板 + 保存后重新诊断”；
- 后续再做“应用内可视化样式编辑器”。

#### 7.2.5.4 “用 Word/WPS 打开编辑”交互

点击后弹出确认提示，避免用户误以为在 md-king 里编辑正文内容。

```text
用 Word/WPS 编辑模板

注意：模板正文内容不会出现在转换后的文档中，md-king 主要使用这个文件里的样式设置。

修改完成后，请在 Word/WPS 中保存文件，再回到 md-king 点击“重新诊断”。

[取消] [打开编辑]
```

打开后，模板编辑抽屉顶部显示一个提示条：

```text
模板已在 Word/WPS 中打开

[重新诊断]
```

#### 7.2.5.5 替换模板文件流程

用户可能已经在别处准备好了新的 `.docx` 模板，需要替换当前模板文件。

```text
替换模板文件

选择一个新的 .docx 文件替换当前模板。模板名称、分类、标签和说明会保留，但样式诊断结果会重新生成。
```

#### 7.2.5.6 应用内样式设计器设计（后续版本）

如果后续要做到“用户不打开 Word/WPS，也能在 md-king 里改模板样式”，不能把样式编辑做成固定的 `标题 1 / 标题 2 / 标题 3` 三个按钮。实际 Markdown 和 Word 场景里至少会用到：

- Markdown 标题：`H1` 到 `H6`；
- Word 内置样式：`Heading 1` 到 `Heading 6`、`Normal`、`Body Text`、`Quote`、`Source Code`、`Caption` 等；


其中 `样式管理` 是核心页面。

## 20. 设计师重点注意事项

1. 这个产品核心不是“编辑 Markdown”，而是“把 AI Markdown 快速转 Word/WPS”。
2. 首页要突出拖拽、粘贴、模板、转换按钮。
3. 模板中心要有明显的“Word 样式模板”感。
4. 错误提示要面向普通用户，不要只展示底层技术错误。
5. 文案要强调本地转换和隐私安全。
6. 不要做成传统后台系统，也不要做成复杂 Markdown IDE。
7. MVP 可以先保证核心转换体验漂亮、清晰、可靠。
