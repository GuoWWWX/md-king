# md-king UI 风格方向：柔和玻光蓝

> 当前选定方向：Variant C，柔和玻光蓝。它是 md-king 后续桌面端界面改造的主视觉方向。

## 1. 设计定位

md-king 应该像一个好用、可信、长期放在桌面上的文档效率工具，而不是营销页或后台管理系统。

核心感受：

- 明亮、干净、专业。
- 蓝色主题，避免紫色 AI 渐变感。
- 有轻微立体感和玻璃层次，但不厚重。
- 信息清楚，第一眼知道怎么把 Markdown 转成 Word。
- 对“本地转换、隐私安全、模板复用、Agent 调用”表达明确。

## 2. 视觉关键词

- 柔和蓝色玻璃。
- 半透明浅蓝面板。
- 细腻内高光。
- 蓝色环境阴影。
- 圆润但严谨。
- 桌面生产力工具。
- AI 文档工作流友好。

避免：

- 大面积深色科技风。
- 紫色霓虹和通用 AI SaaS 风。
- 纯白扁平卡片堆叠。
- 过度拟物导致界面笨重。
- 把未实现功能包装成已完成能力。

## 3. 基础 Token 建议

### 3.1 色彩

```text
App background: #EAF4FF / #F4FAFF
Glass surface: rgba(255, 255, 255, 0.58)
Glass blue surface: rgba(218, 237, 255, 0.62)
Primary blue: #2563EB
Deep blue: #1E3A8A
Soft cyan: #7DD3FC
Text strong: #0F172A
Text normal: #334155
Text weak: #64748B
Border glass: rgba(255, 255, 255, 0.72)
Border blue: rgba(147, 197, 253, 0.46)
Success: #059669
Warning: #D97706
Danger: #DC2626
```

主色只用于当前导航、主按钮、焦点态、关键状态和少量视觉高光。

### 3.2 圆角

```text
App shell: 28px
Main panel: 24px
Card: 20px
Input/Button: 12px
Badge/Pill: 999px
Floating ball: 999px
```

同一层级不要混用太多圆角。玻璃主面板可以更圆，表单控件要更克制。

### 3.3 阴影和玻璃

```css
background: linear-gradient(135deg, rgba(255,255,255,.72), rgba(219,234,254,.46));
backdrop-filter: blur(22px) saturate(160%);
border: 1px solid rgba(255,255,255,.72);
box-shadow:
  inset 0 1px 0 rgba(255,255,255,.72),
  0 24px 80px rgba(37,99,235,.14);
```

阴影使用蓝色环境阴影，不使用纯黑重阴影。

## 4. 页面系统

当前 C 风格页面设计稿：

1. 转换工作台：主链路，粘贴/导入 Markdown，选择模板，生成 Word。
2. 模板中心：模板试用、默认模板、导入模板、样式能力入口。
3. 转换历史：找回最近生成的 DOCX，复制路径、打开文件、重试失败任务。
4. 快速入口：悬浮球、快捷键、右键菜单、系统托盘等无感入口。
5. Agent 与命令行：CLI、stdin、JSON 输出、Agent 调用流程、本地服务状态。
6. 设置中心：转换默认值、Pandoc、输出目录、外观、系统集成、隐私数据。
7. 关于与系统状态：版本、能力摘要、本地隐私、依赖检测、更新与反馈。

设计资产见 [design-assets/README.md](design-assets/README.md)。

## 5. 实现原则

- 先统一 App Shell，再改每个页面。
- 主转换页优先，模板中心第二，历史页第三。
- 快速入口和 Agent/CLI 页面可以先做“规划中/即将支持”的真实状态，不要伪装成已经可用。
- 设置页只放低频配置，不要抢主转换流程。
- 所有页面都需要空状态、错误状态和加载状态。
- 页面内容以中文短句为主，按钮文案直接，比如“生成 Word”“读取剪贴板”“导入 Markdown”“打开 DOCX”。

## 6. 实现顺序建议

1. 建立 C 风格全局 CSS token：背景、玻璃面板、按钮、徽标、输入框。
2. 重做 App Shell：侧边导航、顶部状态栏、窗口背景和主内容容器。
3. 重做转换工作台：编辑区 + 右侧转换面板 + 结果区。
4. 重做模板中心和历史页。
5. 补快速入口、Agent/CLI、设置、关于页面。
6. 再做悬浮球小窗、右键菜单确认弹窗、批量队列等状态页。

## 7. 诚实状态标注

当前已规划但不应在 UI 中表现为完全可用的能力：

- Windows 右键菜单。
- 悬浮球。
- 系统托盘。
- 全局快捷键。
- CLI / Agent 本地服务。
- MCP Server。
- 完整批量队列。

这些能力可以有设计入口，但必须明确状态，例如“规划中”“待接入”“需要安装集成”。
